# Making the Keyman keyboard for iPad as strong as Keyman allows

Keyman keyboards are rules plus a touch layout. They run inside the Keyman app, without network access, and they cannot read a word list from Sulekhak. So the plan is to move as much as possible into the places Keyman does give: the touch layout, the rules, and the lexical model.

1. **A touch layout made for the iPad.** Give the tablet its own layout (`tablet` form factor) with the full Odia consonant and vowel rows, a number row, long-press (subkeys) for matras, conjunct starters and the rare signs, and flicks for the most common alternates. Layers: default, shift, a symbols layer, and an Odia-digits layer. Keep the language switch and the globe key in the same place on every layer.
2. **Rules that match the PC engines.** Keep one source for the key mapping (`core/keymap/sulekhak-keymap.json`) and generate the `.kmn` from it, the way the Windows and Mac tables are generated, so the rules cannot drift. Cover: halant followed by ZWNJ before ବ, the `ru` forms, nukta on ଡ/ଢ, `khy` giving କ୍ଷ, `w` giving ୱ. Test with the Keyman compiler's own tests and a table of typed inputs and expected outputs.
3. **A lexical model for suggestions and correction.** Build the model from the 250,000-word weighted list (word, count) in the Keyman `.model.ts` wordlist format, per language. Add the apostrophe words (ତା'ର, କ'ଣ, ମା' …) as ordinary entries so they appear beside the plain forms. Keyman models score single words, so context (the bigram and trigram model) needs a custom `predict` function; keep it small, because it runs on the phone.
4. **English.** Ship a second keyboard (or a layer) whose model is built from `en_lex.txt`, with contractions and the new technical vocabulary already inside. English capital letters and curly quotes can be done in rules (`context` and `any`/`index`), so the polish matches the other platforms.
5. **A hardware-keyboard layer.** iPads are often used with a keyboard; give the package a desktop layout with the same rules, so Shift+Tab, digits and punctuation behave like the PC apps where Keyman allows.
6. **Fonts.** Package a font that shows ZWNJ and the conjuncts correctly (Noto Sans Oriya), so the key caps and suggestions do not show boxes.
7. **Build and test in CI.** Compile with `kmc` on every change, run the keyboard's regression table, and fail the build if the compiled output changes without the table changing. Publish the packages to the repository releases, and, if you want automatic updates inside the Keyman app, submit them to the public keyboards repository (it requires an open licence).
8. **What Keyman cannot give.** No swipe typing, no Google sync of learning, no Add-to-dictionary from the keyboard, and no access to the Sulekhak learning files. For those, the Sulekhak iPad app is the better choice; use Keyman when a system-wide, no-install-of-a-full-keyboard-app option is needed or on devices where only Keyman is allowed.
